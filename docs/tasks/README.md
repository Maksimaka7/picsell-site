# docs/tasks — черга завдань для Claude Code

Сюди Chat-Claude кладе технічні завдання (ТЗ) і патчі до них.
Максим більше не пересилає файли вручну — він лише називає номер ТЗ.

## Як це працює

1. Chat-Claude комітить у `main`:
   - `docs/tasks/TZ-NN-<назва>.md` — саме завдання
   - `docs/tasks/patches/<назва>.patch` — готовий діф, перевірений локальною збіркою
   - для великих задач замість патча може бути файл даних у `data/` і візуальний еталон у `docs/tasks/proto/`
2. Максим пише в Claude Code: **«зроби TZ-NN»**
3. Claude Code читає ТЗ, застосовує патч, збирає, комітить, пушить і звітує

## Правила для Claude Code

- **Порядок має значення.** Якщо в ТЗ вказана база (`База: <sha>`), а `main` уже пішов далі — не накочувати наосліп. Спершу перевірити `git apply --check`; якщо не лягає, повідомити, а не зводити конфлікти вручну.
- **Патчі одноразові.** Після успішного пушу перенести використаний патч у `docs/tasks/done/` і дописати в ТЗ рядок `Виконано: <sha>`. Два коміти замість одного тут нормально: рядок `Виконано:` не може посилатися сам на себе.
- **Не мержити нічого без слова Максима** — навіть якщо PR виглядає готовим.
- **Звіт обов'язковий**: SHA коміта, результат кожного критерію приймання, і окремо все, що не вдалося перевірити, з причиною. Не видавати неперевірене за перевірене.
- **Локальна збірка може падати на `_build`** у `content/uk/_index.md` — ключ прибрано з Hugo 0.145+, а локально стоїть новіший. Netlify запінений на 0.139 і збирається. Для локальної перевірки допустимо тимчасово підмінити ключ на `build:` і повернути перед комітом.

## Правила для анімацій

Вироблені під час серії ТЗ-09…ТЗ-14 і підтверджені замірами на проді. Діють на всі нові анімації, не лише на героя.

- Анімувати **тільки `transform` і `opacity`**. `top`, `box-shadow`, `width` у кейфреймах — це перерахунок розкладки й перемальовування на кожному кадрі.
- Кожна анімація **завмирає за екраном і у фоновій вкладці**: `IntersectionObserver` плюс `visibilitychange`, клас-пауза з `animation-play-state`.
- `prefers-reduced-motion` показує **статичний фінальний кадр**, а не порожнечу.
- Затримки задавати **явними класами, не `nth-of-type`** — він рахує всі елементи свого типу, а не лише ті, що мають потрібний клас, тож серед різнотипних сусідів мовчки не збігається.
- Перед тим як покласти текст у SVG-плашку — порахувати ширину: моноширинний 10px ≈ 6.0 px на символ.

## Пастки Hugo, на які вже наступали

- **`jsonify` у `<script>` приїжджає рядком.** У JS-контексті шаблонізатор екранує вивід як рядковий літерал — `FEAT.forEach is not a function`. Потрібен `| safeJS`.
- **Партіал усередині `<style>` зникає мовчки.** У CSS-контексті вивід санітизується, весь блок пропадає **без помилки збірки**. Потрібен `| safeCSS`. Найнеприємніший тип дефекту: збірка зелена, стилів немає.
- **`append` сплющує зрізи.** `append (slice .n .r)` додає два елементи, а не пару; обгортання другим `slice` Hugo відкидає через типізацію першого елемента. Складати структури через `dict`.
- **`.Language.Lang` тут завжди `uk`.** Обидва мовні дерева належать до мови за замовчуванням. Мову виводити з URL: `strings.HasPrefix .RelPermalink "/en/"`.

## Відкриті хвости (не ТЗ, потребують участі Максима)

- **Скріншоти застосунку** — у блоці «День у застосунку» стоять намальовані заглушки. Реальні будуть після редизайну застосунку.
- **Токен Telegram** — у секреті `TELEGRAM_BOT_TOKEN` лежить відкликаний токен, сповіщення про заявки не йдуть із `submit-lead`. Ротація у BotFather, передеплой не потрібен.
- **`telegram-notify`** — та сама діра з токеном.
- **Заміри 6–9 з ТЗ-11** — Performance-трасування на проді, потребує вікна Chrome на передньому плані.
- **Пункт 3 з ТЗ-12** — `prefers-reduced-motion` не зміряний, панель не вміє емулювати.
- **Мерехтіння** — до подальших правок коду перевірити incognito без розширень і зняття `backdrop-filter` у DevTools.
- **`_build` при підйомі `HUGO_VERSION`** — перейменувати на `build:`.
- **`/en/sitemap.xml`** — містить одну адресу; англійські сторінки покриті українською картою.
- **Номер підтримки в шапці / `privacy` / `terms`** — свідомо не додано в ТЗ-15.
- ~~**`hreflang` зламаний по всьому сайту**~~ — закрито в TZ-19 (`dd50ee0`). Діагноз був точнішим за мій: `.AllTranslations` парує нормально, ламалася лише мітка мови. Архітектурної перебудови не знадобилось.
- **`translationKey` для 19 пар статей блогу** — слаги UK і EN різні, парування немає, тож у кожної статті одна самопосилальна альтернатива. Відповідність треба звіряти за змістом, не вгадувати.
- **Екрани застосунку в блоці «День у застосунку»** — намальовані заглушки, і лише для мерчандайзера. Іншим ролям картки віддаються без екрана: показувати видошукач камери на сторінці регіонального менеджера було б неправдою. Заміна на реальні скріншоти — механічна.
