## 1. Форма на `/demo/`

### 1.1 Прибрати два поля

Видалити «Посада» (`select name="role"`) і «К-сть агентів» (`select name="agents"`) з **обох мовних блоків** — це чотири елементи разом із їхніми `<label>` і обгортками `.form-group`.

Разом із ними прибрати з payload у `submitDemoForm()`:

```js
position: fd.get('role') || '',
agents:   fd.get('agents') || '',
```

і рядки, які підмішують їх у `message`. Поле `message` після цього збирається лише з `interests`.

**Не чіпати** стаб-форму `demo-request` у `layouts/_default/baseof.html`: Netlify реєструє поля саме звідти, і видалення `role`/`agents` зі стабу зламає наявні записи. Достатньо, що ці поля перестануть надсилатись.

### 1.2 Перейменувати поле

«Ім'я та прізвище» → **«Ім'я»**, англійською «Full Name» → **«Name»**. Атрибут `name="name"` не змінювати — на нього зав'язаний payload.

### 1.3 Поля зробити світлими

Причина видно в CSS:

```css
.form-input, .form-select { background: rgba(6,6,8,.9); }
```

Це майже чорний колір, зашитий хексом ще з темної теми. Після переходу сайту на світлу тему (ТЗ-11) він лишився й тепер вибивається.

Замінити на `var(--bg2)` з бордером `var(--border)` — так поля виглядатимуть як у калькуляторі на головній, де це вже зроблено правильно. Заодно перевірити `::placeholder`: на світлому фоні він має бути `var(--t3)`, а не світлий.

### 1.4 «Незрозуміла плашка зверху»

Це `<div class="interest-role" id="interestRole" hidden>` — рядок «Цікавить роль: …», який ми додали в ТЗ-18 для переходів зі сторінок ролей. Він має `hidden` і показується лише при `?role=…`.

На скріншоті видно порожню синю смугу, тобто **`.interest-role` має фон і відступи навіть коли порожній**. Виправити: стилі застосовувати лише до видимого стану, наприклад через `.interest-role[hidden]{display:none}` або перенести оформлення на клас, який ставиться разом із текстом.

Прибирати саму функцію не треба — вона робоча й корисна.

### 1.5 Чекбокси необов'язкові

Перевірити, чи форма справді не відправляється без вибору. У розмітці `required` на `interests` немає, тож імовірно блокує JS-валідація або HTML5 на групі. Знайти й зняти — форма має відправлятись із порожнім `interests`.

## 2. Ілюстрації на продуктових сторінках

### 2.1 Що насправді відбувається

Ілюстрація **є** — на `/sales-app/` у правій колонці лежить `.phone-mock` із повним макетом застосунку. Вона не зникла, вона **невидима**, бо намальована для темної теми:

```css
.phone-mock  { background: var(--bg3); }   /* у світлій темі #FFFFFF */
.phone-notch { background: var(--bg2); }   /* #F1F3F7 */
.app-header  { background: var(--bg2); }
.route-card  { background: var(--bg2); }
```

Жодного перевизначення під `.theme-light` немає. Виходить майже біле на білому, плюс тінь `rgba(0,0,0,.5)`, розрахована на темний фон.

Це наслідок ТЗ-11: тему розкотили на весь сайт, а мокапи всередині продуктових сторінок ніхто не переглядав, бо вони не потрапляли в контрастну перевірку — там перевірявся текст, а не тло блоків.

### 2.2 Що зробити

Додати перевизначення для світлої теми: корпус мокапа лишити білим, а внутрішні картки й шапку зробити на тон темнішими за тло сторінки, щоб вони читались. Тінь замінити на `rgba(15,30,55,.12)`, як у решті світлих карток сайту.

## 3. Подія `generate_lead` на головній

### 3.1 Причина

Код уже написаний і виглядає правильним. У `layouts/partials/analytics-events.html`:

```js
var mainForm = document.getElementById('mainForm');
if (mainForm) { mainForm.addEventListener('submit', function(){ gtag('event','generate_lead', …) }) }
```

Але **на головній немає елемента `<form>` узагалі**. CTA-блок побудований на кнопці з обробником `click` — `ctaSubmit`. Тому `getElementById('mainForm')` повертає `null`, слухач не чіпляється, подія не надсилається.

На `/demo/` є справжній `<form id="demoForm">`, тому там усе працює.

### 3.2 Що зробити

Викликати подію з місця, де відправка **справді відбулась** — у партіалі `layouts/partials/cta-demo.html`, у гілці успіху після відповіді `submit-lead`:

```js
if (window.gtag) gtag('event','generate_lead', {
  event_category: 'conversion', event_label: 'homepage_demo', value: 1, currency: 'USD'
});
```

Це надійніше за слухач `submit`, бо рахуватиме успішні відправки, а не спроби.

**Прибрати мертвий блок** `mainForm` з `analytics-events.html`, щоб наступний, хто його прочитає, не вирішив, що подія вже працює.

### 3.3 Заодно перевірити калькулятор

У партіалі `calculator.html` теж є форма лід-капчуру. Перевірити, чи вона надсилає подію — за тією самою логікою вона могла лишитись без відстеження.

## 4. Критерії приймання

1. Збірка `hugo --gc --minify` без помилок
2. `/demo/` обома мовами: немає «Посада» і «К-сть агентів», поле зветься «Ім'я» / «Name»
3. Поля світлі, плейсхолдер читається, порожньої смуги над формою немає
4. Форма відправляється **без жодного обраного чекбокса** — перевірити реальним сабмітом на прев'ю
5. У payload `submit-lead` немає `position` і `agents`; решта полів на місці
6. `?role=merchandiser` і далі показує рядок «Цікавить роль: Мерчандайзер»
7. Мокап на `/sales-app/` і `/horeca/` видно на світлому тлі, картки всередині відрізняються від тла сторінки
8. **Подія `generate_lead` надсилається з головної** — перевірити в GA4 DebugView або через `dataLayer` у консолі, реальним сабмітом
9. На `/demo/` подія працює як раніше — не зламати наявне
10. Мертвий блок `mainForm` прибрано

Пункт 8 перевіряти саме сабмітом, а не читанням коду: попередній код виглядав правильним і не працював.
