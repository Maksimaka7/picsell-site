# ТЗ-14 · Безумовний start() скасовував засів стану

**Репозиторій:** `Maksimaka7/picsell-site`
**Гілка:** `main`
**База:** `4efebb3` (блоб `layouts/index.html` = `f6ecd98`)
**Патч:** `docs/tasks/patches/drop-unconditional-start-2026-08-17a.patch`
**Оцінка:** 3 хвилини

---

## 1. Контекст — знахідка з огляду ТЗ-13, приймається повністю

Засів стану спрацьовував лише наполовину. `sync()` коректно ставив `anim-idle` і викликав `stop()`, а через кілька рядків у гілці `if(animate)` стояв безумовний `start()`, який запускав canvas-цикл попри фонову вкладку.

Твій замір (`cancels: 1` після `visibilitychange` на свіжому завантаженні без зміни стану) це доводить прямо: `running` було `true`.

Практична вага справді мала — Chrome глушить rAF у прихованих вкладках — але твоє формулювання точне: це суперечить заявленому «`sync()` — єдине джерело правди». Код, який сам собі суперечить, рано чи пізно стане багом при наступній правці.

**Виправлення:** рядок `start()` видалено. `sync()` уже викликає `start()`, коли треба — він стоїть після `build()`, тож canvas уже має розміри, а `visible` ініціалізована в `true`.

Перевірено симуляцією:

| Конфігурація | anim-idle на старті | Цикл на старті |
|---|---|---|
| Десктоп, вкладка активна | false | запущено |
| Десктоп, відкрито у фоні | true | **не запущено** |
| Тачскрін | false | не запущено |

Після появи фонової вкладки цикл запускається, скролом зупиняється й перезапускається — без змін.

## 3. Критерії приймання

1. Збірка без помилок
2. У блоці частинок рівно один виклик `start()` — всередині `sync()`. Безумовного немає
3. **Фонове завантаження:** на свіжому завантаженні в прихованій вкладці інструментувати `cancelAnimationFrame` і кинути `visibilitychange` без зміни `document.hidden`. Має бути **`cancels: 0`** (було `1`) — це той самий замір, яким ти виявив дефект
4. Після появи вкладки: `anim-idle` знято, анімації йдуть, цикл запущений
5. Десктоп у звичайній активній вкладці: анімації працюють одразу після завантаження (головна регресія, яку треба виключити)
6. Тачскрін: `rafRequests: 0` як і раніше

Пункт 5 важливіший за решту: якщо я помилився, частинки на звичайній сторінці взагалі не почнуть рухатись.

---

## 4. Чого НЕ робити

- Не переносити виклик `sync()` вище за `build()` — canvas має отримати розміри до старту циклу
- Не додавати `start()` назад «про всяк випадок»
