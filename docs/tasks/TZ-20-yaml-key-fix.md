# ТЗ-20 · Провідник показує 0 — ключ `n` у YAML читається як «ні»

**Репозиторій:** `Maksimaka7/picsell-site`
**Гілка:** `main`
**База:** `a65b729`
**Патч:** немає — заміна механічна, команда нижче
**Пріоритет:** зламано на проді
**Оцінка:** 10 хвилин
**Виконано:** `c04eeeb`

---

## 1. Що зламано

На всіх чотирьох сторінках ролей і на хабі провідник порожній: лічильник показує `0`, підрядок під ним порожній, сітка категорій не рендериться взагалі. Сцена й вкладки при цьому працюють.

## 2. Причина — моя помилка у файлі даних

У `data/role-features.yaml` кожна позиція записана як `{ n: "Назва", r: "MS" }`.

**Голе `n` у YAML 1.1 — це булеве «ні».** Hugo парсить саме YAML 1.1, тому ключ `n` перетворюється на `false`, а `.n` у шаблоні не знаходить нічого і віддає `null`.

Перевірив прямо, а не за здогадом. Тимчасовий файл `{ n: "значення-n", r: "значення-r", name: "значення-name" }` після рендеру дав:

```
keys=[false:значення-n  name:значення-name  r:значення-r]
```

Ключ `n` буквально став `false`. У зібраній сторінці це видно як `{n:null,r:"MS"}` — `r` вцілів, `n` знищено. Звідси нуль: JS фільтрує позиції, у всіх `name` порожній, рендерити нічого.

Другий тест підтвердив, що так само поводяться `y`, `on`, `no`, `off`, `true`, `false` — три різні ключі в одному об'єкті схлопнулися у два.

## 3. Що зробити

**Крок 1 — дані.** Перейменувати ключ у `data/role-features.yaml`:

```bash
git checkout main && git pull
sed -i '' 's/{ n: /{ name: /g' data/role-features.yaml     # macOS
grep -c '{ name: ' data/role-features.yaml                  # має бути 238
grep -c '{ n: '    data/role-features.yaml                  # має бути 0
```

Дописати в шапку файла, щоб ніхто не повернув коротке ім'я:

```yaml
# key `name` is spelled out on purpose: a bare `n` is boolean false in YAML 1.1,
# which is what Hugo parses, so `{ n: "..." }` silently became a false-keyed entry
# and every item name rendered as null.
```

**Крок 2 — шаблон.** У `layouts/partials/role-explorer.html` (і будь-де ще, де читається карта можливостей) замінити звернення `.n` на `.name`. Ключ `r` не чіпати — він працює.

**Крок 3** — збірка й перевірка.

## 4. Критерії приймання

1. Збірка без помилок, 67 сторінок
2. `grep -c '{ name: '` → **238**, `grep -c '{ n: '` → **0**
3. У зібраній `/roles/supervisor/index.html` payload містить справжні назви, **жодного `null`**: `grep -c 'n:null'` або еквівалент для нового ключа → 0
4. Лічильники живцем у браузері: **47 / 89 / 56 / 123**, напрямів **12 / 13 / 12 / 18**
5. Сітка категорій рендериться, назви читаються, пошук фільтрує
6. Те саме на `/en/roles/…` і на хабі `/roles/`
7. Регресій на решті сайту немає

Пункт 3 важливіший за інші: він ловить саме той дефект, який пройшов повз усі попередні перевірки.

## 5. Чому це не спіймалося раніше

Дефект мовчазний з обох боків. Збірка зелена, помилки немає. Дані валідні для PyYAML, яким я перевіряв файл перед комітом — PyYAML не вважає одинарне `n` булевим, а бібліотека Hugo вважає. Тобто перевірка на моєму боці проходила, а на проді ламалося.

**Це четвертий випадок за два дні, коли перевірка джерела дала зелене світло, а зібраний вивід був зламаний** — після `safeJS`, `safeCSS` і hreflang із лапками. Спільне в них одне: перевіряти треба **зібраний вивід**, а не вихідний файл.

Додай, будь ласка, до розділу «Пастки Hugo» в README ще одну: **короткі ключі YAML**. `n`, `y`, `on`, `no`, `off` стають булевими; імена ключів писати словами.
